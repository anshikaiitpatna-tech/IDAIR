Build a fully functional web app called "Bulk ID Studio" — it turns one SVG design template + a spreadsheet into press-ready ID cards, generated in bulk.

DESIGN REFERENCE:
Use a clean, minimal SaaS studio look — off-white background, dark sidebar-free top nav, a 4-step horizontal progress tracker (Upload → Map fields → Review → Export) with numbered circles and connecting lines. Three-column workspace layout:
- Left column: "Source files" panel — drag-drop zone for new files, list of uploaded files (SVG template + CSV/XLSX) with file size and a green checkmark when parsed successfully.
- Center column: "Live Preview" — a canvas showing the current card design rendered with real data from one row, a zoom control, a "Showing [Name] · row X of Y" label below it, and below that a "Generated Preview" grid showing several sample cards side by side with a "Ready" status tag per card.
- Right column: "Quality Check" panel — shows counts like "Fields mapped: 4/4", "Photos matched: 246/248", "Rows imported: 248", and a warning box listing specific unresolved issues (e.g. "Lina Joseph — photo filename not found", "Nisha Patel — Roll No is empty"). Below that, a "Field Mapping" section listing each detected token (e.g. {{Name}}, {{Roll No}}, {{Department}}, {{Photo}}) next to a dropdown to map it to a spreadsheet column, with a "Synced" status label. A prominent "Generate preview" button at the bottom.

Match this visual style: rounded cards with soft shadows, small uppercase gray labels (like "STEP 02 / LIVE PREVIEW"), a muted sage-green accent color, monospace-style small text for metadata, and generous whitespace.

REAL FUNCTIONALITY (this must actually work, not just look like it works):

1. SVG Template Upload & Parsing
   - Accept an uploaded .svg file.
   - Parse it and auto-detect placeholder tokens in text elements — patterns like {{Name}}, {{Roll No}}, {{Department}} — and a designated photo placeholder (an element with id="photo-placeholder" or similar, or a shape tagged {{Photo}}).
   - List all detected tokens in the Field Mapping panel automatically — do not hardcode them.

2. Spreadsheet Upload & Parsing
   - Accept .csv or .xlsx (use "papaparse" for CSV, "xlsx"/"sheetjs" for Excel).
   - Read headers and all rows into a data table in memory/state.
   - Let the user map each spreadsheet column to a detected SVG token via dropdowns. Persist this mapping in app state.
   - One column should be mappable as the "Photo" source — either a URL per row, or a filename to match against a bulk-uploaded ZIP of images.

3. Live Preview Rendering
   - For the currently selected row, clone the parsed SVG, substitute each mapped token with that row's real value, embed the matched photo (crop/fit into the photo placeholder's bounding box, preserve aspect ratio), and render it live on the canvas.
   - Row navigation (prev/next or "row X of Y") should re-render the preview with real data each time — no placeholder/fake data.

4. Quality Check (must reflect real state, computed live)
   - "Fields mapped" = count of tokens that have a column mapped / total tokens detected.
   - "Photos matched" = count of rows where the photo column value resolved to an actual image (URL loads or filename found in uploaded ZIP) / total rows.
   - "Rows imported" = actual row count from the parsed spreadsheet.
   - Issues list = actually generated by scanning rows for missing mapped fields or unresolved photos, with the real row's name/identifier shown, not sample text.

5. Bulk Generation
   - "Generate preview" renders a small sample (e.g. first 5 rows) as actual rasterized PNGs client-side or server-side (use resvg-js, sharp, or canvas-based SVG rendering — pick what's easiest in a Replit Node environment).
   - A separate "Generate all" / Export step renders every row into a PNG, packages all of them into a downloadable ZIP (use jszip), and also produces one combined print-ready PDF (standard CR80 card size 3.375in x 2.125in, multiple cards per page, use pdf-lib or pdfkit).

6. Step Navigation
   - The 4-step tracker (Upload → Map fields → Review → Export) should reflect real app state — each step only becomes active/clickable once its prerequisite is done (e.g. can't reach "Map fields" until both files are uploaded and parsed).

TECH STACK:
- Frontend: React + Tailwind, functional components, clean state management (useState/useReducer or Zustand).
- Backend (if needed for heavy rendering): Node.js/Express on the same Repl.
- Libraries: papaparse, xlsx (sheetjs), jszip, pdf-lib or pdfkit, resvg-js or sharp for SVG-to-PNG rasterizing.
- No external paid APIs. Everything runs inside one Repl.

IMPORTANT: Every number, list, and preview shown in the UI must come from real parsed data and real computed state — no hardcoded sample values like "Maya Sen" or "248 rows" left in as static placeholders once real files are uploaded.
